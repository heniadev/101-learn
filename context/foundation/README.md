# context/foundation

Dokumenty żywe, które przekraczają pojedynczą zmianę. Każdy projekt bierze
te, których potrzebuje — wymagania, wybór stacku, roadmapa, lekcje, plan
testów. Każdy z nich należy do skilla, który go czyta i zapisuje.

Trzy konwencje:

- **Edycja na miejscu.** Gdy dokument fundamentu zmienia się przyrostowo,
  poprawiaj istniejący plik. Nie twórz datowanych kopii „na wszelki
  wypadek".
- **Archiwizacja dopiero przy zastąpieniu.** Dokument zastąpiony nowym
  podejściem — a nie po prostu dopracowany — wędruje do
  `foundation/archive/YYYY-MM-DD-<dokument>.md`, a jego miejsce zajmuje
  następca pod pierwotną ścieżką. Do archiwum nic nie zagląda rutynowo.
- **Nazwany antywzorzec: dokument jednej zmiany w fundamencie.** Wszystko,
  co dotyczy pojedynczej zmiany — jej plan, rozpoznanie, przegląd —
  należy do `context/changes/<change-id>/`, nigdy tutaj. Fundament jest od
  tego, co przeżyje każdą pojedynczą zmianę.
